# Audit C — finance group (2026-11-19)

Scope: quotes-invoices-payments (FIN), refunds-and-credit-notes (RFD), revenue-sharing-and-payouts (REV), subscriptions (SUB), suppliers-landlords-payables (SUP), dashboards-and-reports (RPT).
Method: route grep (server controllers) + service/domain read + web page/hook grep. Paths are relative to `server/src` and `web/src`.

## Systemic finding (read first)

**G0. [CLOSED wave 2: directory reads applications/users/catalogue; case + plan invoices from real payments.] The finance workspace is not wired to real cases.** `modules/finance/finance.store.ts:313-340` keeps a denormalised "party directory" (clients, workers, services, cases) in `finance_records`, filled by the seed; `syncParty()` is never called anywhere (grep: only its definition). So quotes, invoices, refunds, allocations and payouts in `/finance` work against seeded cases, not `applications`/`users`. In parallel, the client side reads a different source: `payments.service.ts:1288` `myInvoices` derives invoices from `applications.paymentAmount` ("shortcut: … read finance invoices once finance lands"), `creditBalance: 0` hard-coded (`:1332`). Only bank-transfer proofs bridge into finance docs (`payments.service.ts:1134`). Many rows below are DONE as a workspace but their end-to-end flow depends on G0.

Status counts below rate the feature as built; "(G0)" marks ones whose real-data path is blocked by this.

## Gaps (by phase)

### P1

1. **G0 finance ↔ real cases (L).** Replace seeded party directory: `directory()` reads `applications`/`users`/`services` (or call `syncParty` from application create/update + user events); make `GET me/invoices` read finance `invoice` docs and `creditBalance` from `client_credit`; auto-create a finance invoice when an application reaches payable state.
2. **SUB-04/05/06 renewal + dunning (M).** Daily cron `subscriptions.renew`: at `period_end − 7d` create plan invoice (reuse/finish `runRenewals`), outbox reminders T-7/T-3/T-0/T+3/T+7; add `past_due` status for 7-day grace then `expired`; `activateFromPayment` extends from `currentPeriodEnd` not `now`.
3. **SUB-07 self-cancel (S).** `POST me/subscription/cancel {when: period_end|now, reason}` + `cancelAtPeriodEnd` column, honoured by expiry cron; cancel dialog in `billing.tsx` plan tab.
4. **FIN-16 automated reminders (S).** Cron `finance.invoices.remind` daily over issued invoices with balance>0 at offsets [-3,0,3,7,14], reusing `remind()`; idempotency key per invoice+offset.
5. **FIN-04/06/02 PDFs (M).** Server routes `GET me/invoices/:no/pdf`, `me/receipts/:no/pdf`, `finance/quotations/:no/pdf`, `finance/credit-notes/:no/pdf` using existing `textPdf` (chat.service) as interim.
6. **FIN-03 price calculator (M).** `domain/finance/price.ts quoteLines(service, answers, urgent)` producing fee/surcharge/gov/third-party/discount from `services` + `service_pricing_tiers`; used by `createQuote` and `payments.feesFor`.
7. **RPT-01/02 metric registry + definitions (M).** `domain/reports/metrics.ts` with key/label/definition/unit/owner; report frame definitions and overview tiles read it.
8. **FIN-12 field cash confirm route (S).** Add `POST finance/cash/:id/confirm` (web calls it) or repoint the web queue to the existing manual-payment confirm.
9. **SUB-12 80% warning (S).** Banner in `billing.tsx` + notification when used/cap ≥ 0.8.
